## 状态含义

| 状态 | 含义 | 能不能引用 |
|---|---|---|
| 有效 | 结论仍在用 | 能 |
| 有效·需维护 | 结论仍成立，但内容是当前状态的快照，结构一变就会过期 | 能，引用前先核对 |
| 部分被替代 | 主体成立，某几节已被后来的文档取代 | 只能引用未被替代的部分 |
| 历史记录 | 只作过程证据 | 不能当当前基线 |

## 维护规则

1. **新增文档**：编号顺延，状态填「有效」，同时在本表补一行。
2. **结论被推翻时不要重写旧文档。**旧文档顶部加一行 `> 已被 DOC-XX 替代`，状态改「部分被替代」或「历史记录」，正文保留原样。重写会让历史失真，而且 diff 里看不出到底发生了什么。
3. **快照型文档（DOC-03、DOC-09）** 每次结构变化后要回来改，或者干脆改成"只记方法、不记数量"。
4. **本文件不记录实现细节**，只记录"哪篇能信"。

## 为什么不做严格意义上的 ADR

ADR 的做法是"一个决策一个文件、永久不改、可索引"。这套项目没有采用，原因是：
现有 `docs/` 是"一天一文件"的叙事体，改成 ADR 会变成两套并行记录，两边都会过期。
折中办法是**保留叙事体 + 用本索引管状态**：决策理由留在叙事里，可引用性由这张表控制。
