## 三、代码地图（`app/`）

| 文件 | 职责 | 关键约束 |
|---|---|---|
| `graph/llm.py` | 三 provider（deepseek / ollama / openai）+ `BASE_URL` + `CALL_TIMEOUT` | key 优先 `FDE_API_KEY`，回落 `DEEPSEEK_API_KEY`；`CALL_TIMEOUT` 默认 120s（本地 180s） |
| `graph/nodes.py` | 全部节点：understand / plan / act / verify / finalize / lookup / knowledge / ask_user | `SYSTEM_PROMPT` 9 条；`MAX_STEPS=12`；`MAX_CTX_TURNS=2`；所有 LLM 调用走 `CALL_TIMEOUT` |
| `graph/build.py` | 图装配 + `run()` 入口 | `compile(checkpointer=get_saver())`；`run_start` 记 provider/base_url |
| `graph/state.py` | State 定义与合并策略 | `messages`/`evidence` 累积；`tool_names`/`blocked` 覆盖 |
| `graph/persistence.py` | PostgresSaver 进程内单例 | 单例共享一条连接 → **不是线程安全的**，并发前必须处理 |
| `tools/schemas.py` | 8 个工具定义（给模型的 schema） | 取证要求写在 description，不写提示词 |
| `tools/db.py` | 连接与查询基础 | `FDE_PG_DSN` |
| `tools/diagnosis.py` | `query_device_profile` / `query_defect_log` | `GROUP_EXPR` 支持 station/batch/defect_type/day |
| `tools/manual.py` | `search_manual` / `check_doc_conflict` | 用 `params` JSONB 比对，不用正则抽数字 |
| `tools/workorder.py` | `query_work_order` / `create_work_order` | 查：三态（device_not_found/no_order/found）；建：三道检查 |
| `trace.py` | 轨迹落盘 | `runs/<YYYYMMDD_HHMMSS_xxxx>.jsonl`；`contextvars` 存当前 tracer |
| `web/server.py` | FastAPI：`/`、`POST /api/diagnose`、`GET /api/runs`、`GET /api/runs/{id}` | 参数名是 `msg`；`session_id` 走 `_ID_RE` 校验；**同步 def，会阻塞 40–130s** |
| `web/static/index.html` | 单页界面，无框架无 CDN | 改它通常不用重启（FileResponse 每次读盘） |

**8 个工具的能力边界（重要）**：读写工单都有（`query_work_order` + `create_work_order`）；
但**没有跨设备对比/排序**；**没有保养到期计算**（字段有、模型自己算）；
告警码已于 2026-11-16 补进手册库（`device_manual_chunks` 33 块）；`search_manual` 只查本项目手册表，
不跨项目一的 `doc_chunks`。

## 四、脚本地图

### 4.1 日常用

| 脚本 | 用途 |
|---|---|
| `scripts/start.ps1` | 一键起：检查 PG/Ollama/key → 起 8010 + 8020 → 健康检查（会打印 provider/model/base_url） |
| `scripts/run_case.py "问题"` | 命令行跑单条诊断，会落盘轨迹 |
| `scripts/replay.py --list` / `--id <id>` | 回放轨迹 |
| `eval/run_eval.py` | 全量评测；`--only=H1,I2,W1` 跑子集（快 10 倍） |
| `scripts/prune_checkpoints.py` | 清 checkpoint，先 `--dry-run` |

### 4.2 换 provider / 调成本时用

| 脚本 | 回答什么问题 |
|---|---|
| `probe_provider.py <base> <model>` | 这个端点真的返回 `tool_calls` 吗（不返回就根本不能用） |
| `probe_compat.py` | `json_object` 是否支持、缓存字段是否可用、连发 12 次是否限流 |
| `probe_cache.py` | 缓存是否跨请求生效、粒度多大（实测按 2048 token 块） |
| `probe_latency.py` | 慢是排队还是生成（实测中位 2.1s，偶发 7.6s） |
| `probe_parallel.py` | 并发几档触发 429（实测并发 3 通过、6 触发"请 12 秒后再试"） |
| `probe_tools_time.py` | 7 个工具各自耗时（全部 0.05–0.28s） |
| `dig_latency.py` | 一条轨迹的时间花在 LLM 还是工具（实测 LLM 占 92–99%） |
| `dig_tokens.py` | 单条轨迹逐次 plan 的 token 与缓存命中 |
| `stats_tokens.py` | 按 `run_start.model` 分组统计 token / 耗时 / 步数 |

### 4.3 验证与审计

| 脚本 | 用途 |
|---|---|
| `smoke_web.py` | Web 五项冒烟（首页/诊断/历史/回放/空输入） |
| `smoke_web_session.py` | 多轮会话冒烟 |
| `smoke_multi_turn.py` | 补设备 / 换设备 / 摘要累积 |
| `smoke_tools.py` / `smoke_qms.py` | 工具层 / mock QMS 冒烟 |
| `audit_verify.py` | 校验层拦截率审计（实测 0% 真实拦截） |
| `test_intent_parse.py` | 意图 JSON 容错验证（全 mock 不联网；覆盖 ```json 包裹 / 前导说明 / 截断 / 超时四条路径） |
| `test_judge.py` | 判定器严格度验证（构造 state 直调 `judge()`；含"1 号工位带空格"case 与老用例对照组） |
| `check_ctx.py` | 上下文裁剪是否按轮切、配对是否完整 |

### 4.4 本地模型专用

| 脚本 | 用途 |
|---|---|
| `probe_ctx.py` | Ollama 原生 `/api/chat` 看 prompt 是否被截断（默认 2050，需 8192） |
| `probe_ctx_v1.py` | 验证 `/v1` 端点 `extra_body` 透传 num_ctx 是否有效（**实测无效**） |
