# 留档约定

适用于本仓库里的 Agent 项目（当前是 `fde-diagnosis-agent`）。
目的不是"留档完整"，是能回答一个问题：**这次改动有没有让之前对的东西变错。**

## 四层，各管一件事

| 层 | 回答什么问题 | 载体 | 谁产出 |
|---|---|---|---|
| 1 代码变更 | 改了哪些行 | Git commit | 每次改动一条 |
| 2 决策理由 | 为什么这么改、牺牲了什么 | commit message 的取舍段 + `docs/` | AI 起草，人确认 |
| 3 运行时轨迹 | 实际跑了什么 | `runs/*.jsonl`（`run_start` 带 commit / code_hash） | `Tracer` 自动 |
| 4 回归结果 | 有没有把之前对的弄错 | `eval/report_*.json` 的 `meta` | `run_eval.py` 自动 |

**只有第 4 层能回答"有没有变错"，前三层都不能。** 所以哪一层最不能凑合，是清楚的。

## 四条硬规则

### 1. commit message 三段式

改了什么行为 / 牺牲了什么 / 跑过哪些用例。

第二段是唯一无法从代码里读出来的东西——第一段 `git show --stat` 看得出来，第三段可以复跑。
所以**缺取舍段，等于藏代价**。

### 2. 版本号由组件自己采集，不由调用方传参

`Tracer.__init__` 自己取 `commit` / `code_hash`，`run_eval.py` 自己取。
理由：每加一个入口就要求调用方记得补参数，漏一次断一条链，且断得没有痕迹。

两个看起来像 bug、实际是正确语义的行为：

- 代码改了但没提交时，`commit` 仍是上一个——轨迹要记"跑的是哪份代码"，不是"工作区现在什么样"。
- `lru_cache` 让长驻服务不重启就不更新 `commit`——没重启跑的确还是旧代码。

### 3. 两份报告可比，必须四字段全同

`model` / `commit` / `code_hash` / `cases_hash`，且 `meta.evaluated` 相同。

`code_hash` 用**整文件指纹**而非正则抽 prompt 常量：正则抽取会因为改个变量名就失效，而且会漏掉 `schemas.py` 的 enum 白名单——那个 enum 是模型可见行为，枚举写错会改掉幂等键。
代价是**改注释也会让指纹变**，宁可误报。

`meta.evaluated` 解决另一类混淆：`--only=` 跑单条时报告会写明跑了几条，事后不会把半截报告当基线。

### 4. 文档结论被推翻时，不重写正文

做法：顶部加 `> 已被 DOC-XX 替代`，状态改掉，原话用删除线保留，后面补新结论。

理由：重写会让历史失真，而且 `git diff` 里看不出"当时怎么写的、后来改了什么"。
文档被改得像一直就是对的，等于把一次认知修正抹掉了。

## 不做什么

| 否决项 | 理由 |
|---|---|
| 新建 `adr/` 目录 | 与 `docs/` 的"一天一文件"叙事体并行，会造成两套过期记录。改为一张索引管状态 |
| 上 OTel / LangSmith | 换 SDK 要重做已经做好的"写失败静默"，收益只是"能被 Jaeger 读"，对 demo 是零 |
| 抄完整 PR 模板 | 个人项目没有 reviewer，简化成 commit 三段式 |
| 让 AI 在代码里写叙事性"思考注释" | 代码一漂移注释就过期，形成比没注释更坏的虚假解释 |

## 两个观察点

- `runs/` 里 92 条早期轨迹没有 `commit`，是"之前某天跑过"的孤儿，不可补、不可归因。
  从 2026-11-16 起每条都带，回归能定位到单个 commit。
- 四层里只有第 2 层需要人参与。其余三层跑起来就自动留痕，所以人唯一要做的动作是：
  **改动前给出一句约束或交付标准**。
