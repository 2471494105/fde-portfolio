# 档 C：把 `ref` 从"编号"换成"工具名"

> 一句话：编号是**位置**，会随上下文裁剪和轮次漂移；工具名是**身份**，第几轮调都叫同一个名字。
> 所以不给模型任何编号可抄。

- 日期：2026-11-17
- 上一份：`docs/20261117_04_意图置信与证据编号.md`
- 代码：`app\graph\nodes.py`、`tests\test_guardrails.py`

## 一、为什么要动

`_payload` 印 `[证据 N]` 之后，单轮和两轮都过。但三轮探针（同一个 `thread_id`，
`CTX_VISIBLE_TURNS=2` 使第 3 轮 `lo=2`、第 1 轮证据被裁）跑出相反结局：

| 次 | 第 3 轮 refs | `cited_ok` | `cite_oob` | `path_miss` |
|---|---|---|---|---|
| 第 1 次 | 全落在 `5–13` | 14/14 | 0 | 0 |
| 第 2 次 | `1#,2#,3#,4#,6#,8#,9#` | 0/15 | 6 | 8 |

**第一次是运气。** 模型不是在抄号，是在重建：它的记忆来自 `session_summary`
（那里没有编号），于是按"第一个查的就是 1"补一套；真实编号是全局累计、第 3 轮从 5 起。
两套语义并存，必然错位。

按那条判定标准——**结构改了就根治，靠规则要求就没根治，靠关掉检查就是反着走**——
"在 prompt 里要求它写工具名"属于第二档，不选。把编号从 payload 里删掉才是第一档。

一手依据沿用 Anthropic Citations：模型只输出标准形状，**落成具体位置是程序做的**
（`cited_text` 由 API 从文档切）。对应到本项目，就是"模型给一个稳定的指认物，程序去解析"。

## 二、改了什么

| 位置 | 改前 | 改后 |
|---|---|---|
| `_EV_TAG` | `^\[证据 (\d+)\] ` | 删除 |
| `_TOOL_TAG` | — | `^\[([a-z][a-z0-9_]*)\] ` |
| `_REF_PAT` | — | `^\s*([a-z][a-z0-9_]{2,40})#(.+?)\s*$` |
| `_payload` | `head = f"[证据 {ev_no}] "` | `head = f"[{tool}] "` |
| `act` | `_payload(res, ev_no=ev_no)` | `_payload(res, tool=name)`；`ev_no` 仍算，只作审计 |
| `_load_obj` | 剥 `_EV_TAG` | 剥 `_TOOL_TAG` |
| `_verify_claims` | `by_no = {ev_no: ev}` | `by_tool = {tool: [ev, ...]}` |
| `_verify_quote` | 签名同上 | 同改成 `by_tool` |
| `_render_claims` | 匹配 `N#` | 匹配 `_REF_PAT`，渲染成 `[工具名]` |
| `_data_block` | 参数是 `ev_no` | 参数是工具名 |
| `lookup` | `"ref": f"{ev_no}#..."` | `"ref": "query_work_order#count"` 等 |
| `knowledge` | 片段编号→绝对证据号 | `f"search_manual#chunks[{i}].text"` |
| DIAGNOSE prompt | "ref 写证据序号 + 字段路径" | "ref 写**工具名 + `#` + 字段路径**，不要写第几条" |

`_REF_PAT` 开头要求"小写字母、≥3 字符"是故意的：`1#path` 直接判格式错，
而不是被当成"工具名是 1"再滑进别的分支。

## 三、深坑：三条通道都要改成"任一命中"

编号唯一确定一条证据，**工具名不唯一**——同一个工具一轮里可能调两次。

原来命中定义是"字段取得到就 break"：

```python
for cand in cands:
    g = _get_path(obj, path)
    if g is not _MISS:
        got, e = g, cand
        break
```

换工具名后必然错：模型引的是第二次返回的 `chunks[0].text`，`break` 给的是第一次的。
单测先抓到了这条：

```
漂移上限 0.3 毫米（字段值 标定周期为 90 天 ≠ 0.3毫米）
```

正确形状是"收集所有取得到该字段的返回，逐个比，任一配上即成立"：

| 通道 | 判定 |
|---|---|
| 数值 | 任一条 `_value_match` 成立 → `cited_ok`；全不成立 → `path_bad` |
| 区间 | 任一条文本**两端都对上** → `cited_ok`；全不是文本 → "ref 指向数值字段" |
| 引文 | 任一条原文**包含整段引文**（按 `…` 切段）→ `quote_ok`；全不是文本 → `quote_bad` |

判 `cite_cut` 的条件也从"任一条 truncated"改成"没有一条取得到字段、且有截断证据"。

## 五、档 C 自己的盲点

第 3 轮出现过这个模式：

```
- 划痕类误判率 34.69%[query_defect_log]
- 污渍类误判率 25.42%[query_defect_log]
```

两条来自**第二次** `query_defect_log`（按缺陷分组），ref 写 `groups[0].rate` /
`groups[1].rate`——和第一次（按工位分组）**路径完全相同**。

这次靠"值对得上"兜住了。但那是兜住，不是区分：

- 两次返回同字段同值 → 把"引错哪一次"当成立
- 两次返回不同值 → 模型只能猜，猜错就 `path_bad` 误伤

**一句话：路径能定工具、能定字段，定不到"哪一次调用"。**

三条路线：

| 方向 | 做法 | 性质 |
|---|---|---|
| 规则 | prompt 要求同一工具不重复调用 | 靠规则，不算根治 |
| 结构（轻） | 路径带参数指纹 `query_defect_log{group_by=defect}#groups[0].rate` | 模型要抄参数，可能抄错 |
| 结构（重） | 工具返回里加 `"_call": "defect"` 标签字段 | 改返回结构，`path` 全变，最根治 |

按判定标准，只有第三条算"结构改了就根治"。**留作下一项，未做。**
