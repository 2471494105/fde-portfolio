# 参数指纹：把 `ref` 从"哪个工具"精确到"哪一次调用"

> 一句话：工具名解决了**跨轮漂移**，参数指纹解决**同轮多次调用**。
> 两者都用"身份"，没有一个用"位置"。

- 日期：2026-11-17
- 上一份：`docs/20261117_05_档C引用换工具名.md`
- 代码：`app\graph\nodes.py`、`tests\test_guardrails.py`

## 一、档 C 留下的那个洞

档 C 把 `ref` 从 `7#path` 换成 `query_defect_log#groups[0].rate` 之后，三轮探针第 3 轮出现了这个模式：

```
- 划痕类误判率 34.69%[query_defect_log]
- 污渍类误判率 25.42%[query_defect_log]
```

两条来自**第二次** `query_defect_log`（按缺陷类型分组），但 ref 写的是
`groups[0].rate` / `groups[1].rate`——和第一次（按工位分组）**路径完全相同**。

当时的判断是：**路径能定工具、能定字段，定不到"哪一次调用"。**
校验只能靠"值对得上"兜——同值会把引错当成立，不同值时猜错就误伤。

## 二、为什么用参数，不用序号

第二层身份有两条候选：

| 候选 | 形状 | 问题 |
|---|---|---|
| 调用序号 | `query_defect_log.2#...` | 又是位置。跨轮必漂，跟编号是同一个病 |
| 参数指纹 | `query_defect_log{group_by=defect}#...` | 描述"这次查的是什么"，是语义 |

选参数，依据是前两轮已经验证过的规律：**模型记得住"calibration 里有 records"（强项），
记不住"calibration 是第几条"（弱项）。**

参数正好落在强项那一边——它自己传的 `group_by` 是它现场做的一个业务决定，
它当然记得自己按什么分了组。

一手依据沿用 Anthropic Citations 的形状：多文档时用 `document_index` 指明"哪一份"，
citations 靠"位置 + 文档身份"定位，不靠序号。这里把"文档身份"换成"参数身份"。

## 三、改法

```python
def _call_sig(args):
    """这次调用的参数指纹：device_id=CX-104,group_by=defect"""
    parts = [f"{k}={args[k]}" for k in sorted(args)
             if args[k] is not None and args[k] != ""]
    sig = ",".join(parts)
    return sig if len(sig) <= 80 else sig[:79] + "…"
```

- **键排序**：同一组参数永远得到同一字符串，校验端要做等值比较
- **跳空值**：`{"group_by": None}` 不该让指纹和 `{}` 变成两个身份
- **超长截断**：指纹会挤掉 payload 预算，且没人真能抄下 200 字符。两边同一条规则，仍可比较

三处接上：

| 位置 | 改后 |
|---|---|
| `_TOOL_TAG` | `^\[([a-z][a-z0-9_]{2,40})(\{[^{}]*\})?\] ` |
| `_REF_PAT` | `^\s*([a-z][a-z0-9_]{2,40})(\{[^{}]*\})?#(.+?)\s*$` |
| `_payload` | `head = f"[{tool}{{{sig}}}] "` |
| `act` | `sig = _call_sig(args)`，写进 payload 与 evidence |
| `_render_claims` | 渲染成 `[query_defect_log{group_by=station}]` |

## 四、最关键的一条设计决定：只收窄，不排除

指纹匹配直接用"过滤候选"会有一个致命副作用：

```python
if sig:
    cands = [c for c in cands if c.get("sig") == sig]   # ← 危险
    if not cands:
        stats["cite_oob"] += 1      # 判"被裁出窗口"
        continue
```

问题在于**匹配不上有两种完全不同的原因**：

| 原因 | 应该怎么判 |
|---|---|
| 那次调用在旧轮，被 `_ctx_window` 裁掉了 | `cite_oob`，标灰放行（不该判死） |
| 模型把参数抄错了（`group_by=defcts`） | 真错，应该判失败 |

两者从 `sig` 上看起来一模一样。**如果在这里判 `cite_oob`，第二种就被当成第一种放过了**——
这是把"档 C 修好的口子"重新开回来。

所以最终实现是：

```python
if sig:
    narrowed = [c for c in cands if c.get("sig") == sig]
    if narrowed:            # 只在"确实能收窄"时才收窄
        cands = narrowed
# 收窄不了就退回全部候选，按值继续判
```

抄错参数的那条，会在下面的值比较里被抓住——`11.39%` 对不上 `0.4677`，照样 `path_bad`。
**精度提上去了，失败面一个字没扩大。**

反向断言写在单测里：`test_signature_mismatch_falls_back_instead_of_judging_dead`，
两段——指纹错但值对 → 不判死；指纹错且值也错 → 必须判失败。

## 五、实测

### 单测 95/95（0.087 s）

新增 3 条：

| 测试 | 守什么 |
|---|---|
| `test_payload_carries_arg_fingerprint` | 指纹键排序、跳空值；没有指纹就不打花括号（保持旧形状） |
| `test_ref_with_signature_picks_the_right_call` | 两次返回同字段不同值，带指纹精确命中第二条 |
| `test_signature_mismatch_falls_back_instead_of_judging_dead` | 指纹错不判死；值也错必须判失败 |

### 四条单轮（`report_20261117_1453_6497ecb.json`）

语义 4/4、明确出处率 **47/48 = 97.9%**、引文 12 成 0 败、`引用写错 0/4`。
H1 的结论里直接出现 `[query_defect_log{group_by=station}]`——模型抄对了。

### 三轮（临时脚本）

第 3 轮 refs：

```
query_defect_log{group_by=station}#false_positive_rate
query_defect_log{group_by=station}#groups[0].rate
query_defect_log{group_by=station}#groups[1].rate
query_defect_log{group_by=day}#groups[6].rate
query_defect_log{group_by=day}#groups[0].rate
query_defect_log{group_by=defect_type}#groups[0].rate
query_defect_log{group_by=batch}#groups[0].rate
...
```

**模型在一轮里把同一个工具调了四次，用了四种不同分组，并且每次都把对应指纹抄进 ref。**
这正是上一轮那个"划痕/污渍都写 groups[0]"的盲点，现在结构性地分开了。

| 指标 | 值 |
|---|---|
| 引用 | 14/17 |
| `path_miss` | 0 |
| `ref_bad` | 0 |
| `cite_oob` | 0 |

剩下 3 条：1 条 `path_bad`（模型把 11-07 的 2/7 算成 15.38%），2 条 `unsourced`
（两份文档口径冲突那两条它写了 `ref: null`）——两类都是它自己的问题，不是机制问题。

**这一条同时回答了"模型能力够不够"**：不需要额外训练或微调，只要把可抄的东西印在它看得见的地方。

## 六、留下的问题

| 问题 | 现状 |
|---|---|
| 指纹值里若含 `}` | 会破坏 `\{[^{}]*\}`。现有工具参数都是设备号/枚举/数字，安全；但加新工具时要检查 |
| `lookup` / `knowledge` 的 ref 不带指纹 | 它们每轮固定调一次，本来无歧义。代价是校验时走"全候选"，靠值兜 |
| 指纹和实际参数不完全一致时的表现 | 退回全候选 → 仍能靠值命中，但不享受精度收益。没有单独指标度量"有多少条真的用上了指纹" |
| 全量 25 条 | 仍未跑 |

## 七、一句话总结

档 C 用**工具名**解决了"跨轮漂移"，这一轮用**参数指纹**解决了"同轮多次调用"。
两次改的都是"模型手里拿什么去指认"，没有一次是加一条 prompt 求它自觉。
