# 机制换代之后，注释里的旧名字必须跟着死

> 一句话：`cite_oob` 这个键没变、值也对，但它在三个地方被三种旧措辞解释着。
> 代码是对的，说明是错的——错的说明会让下一个人按旧机制去改新代码。

- 日期：2026-11-17
- 前置：`DOC-20`（引用换工具名）、`DOC-21`（参数指纹）
- 代码：`app/graph/nodes.py`、`app/graph/state.py`、`eval/run_eval.py`、`scripts/audit_verify.py`、`README.md`

## 一、这次改的不是 bug，是"证据链断在说明上"

档 C 把引用身份从 `编号#路径` 换成 `工具名#路径`，代码、单测、prompt、文档全动过。
但有一类东西不会自动跟着变——**散落在注释里的机制描述**。

它们不进单测、不影响分数、跑起来也完全正确，所以没人会去动它。
但下一个人读代码时，会拿它当"现在是怎么工作的"。

### 找到的四处（都是错的，且都会误导）

| 位置 | 旧文案 | 为什么是错的 |
|---|---|---|
| `_new_stats` | `"cite_oob": 0,  # ref 指向不存在的第 k 条` | 现在根本没有"第 k 条"，`cite_oob` 的含义是"这个工具本轮没有返回" |
| `verify` docstring | 四层判定写成 `[...]` 的 `[k]` 语义 | 同上，而且这是最容易被当成"判定清单"的一处 |
| `act` 里 `ev_no` 注释 | "同一编号对应两条证据，`by_no` 后写覆盖先写" | **`by_no` 这个索引在档 C 时已经被删了**。注释在描述一个不存在的实现 |
| `CTX_VISIBLE_TURNS` 注释 | "模型数第 k 条，校验层取 `ev[k-1]`，k 整体错位" | 耦合的强度没变，但形状变了：现在错位表现为"这个工具本轮不可见" |

第三行是最典型的：它读起来像一条重要的设计约束，实际描述的是一个**已经删掉的字典**。
照它去改代码，会去找一个并不存在的 `by_no`。

## 二、顺手挖出来的一处"疑似漏改"，查完发现是对的

`knowledge` 这条路径到现在**还在让模型写片段编号**：

```python
# KNOWLEDGE_PROMPT
"ref": "片段编号"
规则 3. ref 只写片段编号（如 "2"），且必须是你收到的片段编号。
```

然后代码把它翻成工具名：

```python
if r.isdigit():
    i = int(r) - 1
    if 0 <= i < len(chunks):
        c["ref"] = f"search_manual#chunks[{i}].text"
```

看到 `isdigit()` 很容易判"档 C 没删干净"。查清楚之后结论相反：

| 编号来源 | 作用域 | 会不会漂 |
|---|---|---|
| evidence 的 `[证据 N]` | **跨轮全局累计** | **会**。模型跨轮看到的是 `session_summary`（没有号），只能按"我第几个查的"重建一套 |
| chunks 的 `[1]..[5]` | **每次检索重新从 1 排** | **不会**。号就印在它这一轮收到的 payload 里，没有"上一轮的 1"可以混 |

**会漂的不是"编号"这个写法，是"跨轮累计的编号"。** 所以这里保留是合理的，
它的代价只是"依赖这次检索的片段顺序"，而那个顺序是程序当场印给它的。

这条已经写进 `knowledge` 的注释里，防下一次有人"顺手统一下格式"把它改坏——
一改就要动 `_verify_quote` 的解析和单测，而收益是 0。

## 三、改完之后 `cite_oob` 的准确定义

一句话记法：**它表示"这个工具在本轮视野里没有返回"，不表示"编号越界"。**

两者的区别决定了该怎么处置：

| 情况 | 判什么 | 怎么处置 |
|---|---|---|
| 工具调过，但那轮已被 `_ctx_window` 裁出 | `cite_oob` | 标灰放行（模型没编，只是引了它现在读不到的东西） |
| 工具名写错 / 从没调过 | `ref_bad` | 判失败 |
| 工具对、字段路径取不到 | `path_miss` | 判失败 |
| 工具对、字段也对、值对不上 | `path_bad` | 判失败 |

`cite_oob` 之所以不判死：判死等于要求模型记住一段**程序已经从上下文里删掉**的内容。
这是本地实现的选择，不是 Anthropic 的保证——`citations are guaranteed to contain valid pointers`
说的是"引用指向的东西有效"，没说"被裁掉之后引用仍然成立"。

## 四、顺带核对的两处

| 位置 | 结论 |
|---|---|
| `scripts/audit_verify.py` | **不用改**。它量的是"复算漏洞"（全池两两相除能凑出编造值）和"覆盖面漏洞"（绝对量不进校验），两者都跟"怎么指认证据"无关。已在头部加一句说明：别把 A–E 五组当成现行判定清单 |
| `README.md` 第 8 项 | 补一句"这一段是当时改法，`[k]` 编号现已不用，现行契约是工具名+指纹"，指向 DOC-20/21。历史记录不改写，但要标清它属于历史 |

## 五、验证

| 项 | 结果 |
|---|---|
| 单测 | **95/95** |
| `_new_stats()` 键完整性 | 19 个键，`cite_oob` 在位（改注释时删掉过一次键，当场发现并修回） |
| 行为变化 | **无**。只改注释、docstring、README，逻辑零改动 |

改注释过程中真的把 `"cite_oob": 0,` 那一行替换成纯注释过——字典少一个键。
`_new_stats()` 立刻能验：这个函数存在的意义之一就是"少一个键会当场出错"。
**改注释也是改代码，别当成打字。**

## 六、留下的问题

| 问题 | 现状 |

## 七、一句话总结

机制换代时，代码和单测会一起换、prompt 会一起换，**注释往往留在原地**。
它们不报错、不飘红，只在下一个改动的人脑子里种一个错的模型——
这种债没有度量，只能定期扫一遍。
