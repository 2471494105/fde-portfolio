# 判据夹具回归：让量具坏了当场报警

`2026-11-18` · 对应提交 `3e617e3`

## 问题

现在验证一次判据改动只有两条路：

| 路径 | 覆盖 | 代价 |
|---|---|---|
| 跑单测（121 条） | 当场想到的形状 | 0.1 秒，但覆盖的是"我以为会发生的错" |
| 重跑全量（27 条） | 真实数据 | **3178 秒** |

中间那层是空的。太贵所以不会每次都跑，所以判据退化了下一次全量才发现——
`4175d0a` 修的两处（`unit` 没进 items、多候选只取第一个）就是这么拖到全量才暴露的。

## 做法

两层：

- `eval/fixtures/criteria_cases.json`：10 条真实样本，存的是 `32704d4` 那轮的 `final` + `evidence` **原文字符串**（不是解析后的结构），这样重放时走的解析路径和生产一致。
- `eval/check_criteria.py`：本地复算，产 PASS/FAIL + 退出码。`-v` 打实际 counts。

**期望值是把 claim 与 evidence 原文并排核对后写死的**，不是照当次判据输出抄的。否则夹具只会把"现在的错误"钉成"正确"——这正是它要防的事。

## 10 条样本

| 编号 | 覆盖的分支 | 期望 |
|---|---|---|
| H2 | items 元素没有 `unit` 位置：证据 `0.0476`、模型写 `4.76%` | 放过 |
| A3 | 同一工具按 4 种参数各调一次 | 放过（3 条 items 全对） |
| A4 | 多候选 + 工位值写百分数 | items 全对，**亮度那条必须红** |
| A1 | 模型下标错一位（`groups[7]` 想指 11-14，实际在 `groups[6]`） | **必须红**，话术须含"候选值 0.1875" |
| H1 | 三个日期三个亮度值，值都在数组里但配错日期 | 必须红（"配对成立"与"值出现过"的分界） |
| T2 | 定性结论挂数组 | 放过（注明：这次绿是偶然，不是结构修好） |
| W2 | 幂等声称，ref 指亮度历史数组 | 放过 |
| A2 | 22 条单值 claim 全对 | 基线，抓"修一处把另一处弄坏" |
| I5 | lookup 引文通道，10 条 claim 走 quote | 放过 |
| M2 | 该工具被调 2 次，而 ref 没写参数指纹 | 放过（全量里唯一的空档） |

选择原则是**覆盖每一条判据分支**，不是挑通过的。所以 10 条里 3 条期望是红。

## 反向验证

夹具跑绿不算数，要证明它能抓退化。

| 退化方式 | 结果 |
|---|---|
| 删掉百分数归一化那支 | **7/9，退出码 1**，H2 与 A3 报红 → 抓住 |
| "多候选逐数组试"改回 `next()` 只取第一个 | **10/10，退出码 0** → **未抓住** |

第二项没抓住的原因见下节。

## 顺带查出一个自己的 bug

做指纹统计时输出里出现 `group_by=statio`、`group_by=da`——**指纹少了最后一个字符**。

```python
head = s[1:i]                        # i 指向 "}"，head 本身已不含花括号
sig = head[len(tool) + 1:-1]         # 再 -1，吃掉最后一个字符
```

后果：`want = {group_by=station}`、`cp = {device_id=CX-101, group_by=statio}`，子集判断永远不成立，**指纹收窄整层静默失效**，全靠"值比较 + 逐数组试"兜着——验的已经不是生产行为，而所有输出看起来都正常。

它还把统计数字整体带偏：误报"指纹收窄失败 29.9%"，修好后是 **0%**。

与 `isinstance` 那次是同一个病：条件永远不成立，代码不报错，只是"换了条路走"。区别是这次坏的是**量具的量具**。

## 指纹真实使用率

341 条带 ref 的 claim：

| 情况 | 条数 | 占比 |
|---|---|---|
| ref 没写 `{参数}` | 208 | 61.0% |
| 写了指纹，收窄到唯一 1 条 | 133 | 39.0% |
| 写了指纹，收窄到 N>1 | 0 | 0% |
| 写了指纹，一条都匹配不上 | 0 | 0% |
| 收窄不到且候选里 ≥2 个数组 | 6（全在 M2） | 1.8% |

**这张表推翻了昨天一处叙述**：昨天把多条红归因为"模型只抄一两个参数、整串相等比不过、收窄失败退回全候选"。实测是**收窄失败 0 条**——模型写的指纹全部能匹配，它写的是子集，子集判断一直成立。

真正让 A3/A4 变红的是**旧代码要求整串精确相等**这一处。所以"取第一个数组"那个 bug 在这批数据里**从未被真实触发**。

另一个值得单独看的数字：**61% 的 ref 不带指纹**。其中 138 条对应工具一轮只调一次（候选唯一），64 条工具在本轮视野里没返回（走 `cite_oob`），**只有 6 条落在真正的空档**。

即：判据的定位能力，大部分时候靠的是"这个工具在一轮里只调了一次"这个偶然，而不是靠指纹设计。

## 未决

`arrs` 逐数组试（取失败最少的那个）：

- 改回 `next()` 后夹具 10/10、全量 `multi_bad` 仍 0 → **无样本证明它必要**
- 留着它的理由：多个候选时"存在一个解释使 pairing 全部成立"，比随便取第一个更接近判据该有的态度
- 撤掉它的理由：`best_bad` 取最少失败，**本质是放宽**——任一数组能糊弄过去就放过，与"拒绝宽松兜底"冲突

两条都成立，都没有数据支撑。记成**未决**，不写成"已修复"。

要变成"已验证"，需要一条模型引第 2 个数组且写对的样本。现有 27 条里没有。
