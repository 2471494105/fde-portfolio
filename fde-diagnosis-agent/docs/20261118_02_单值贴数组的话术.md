# 单值 claim 指向数组时的报错话术

`2026-11-18` · 对应提交 `4427580`

## 问题

A4 有一条 claim：`value=78`、`ref=query_light_usage#brightness_history`。

实际返回是 `{"brightness_history": [{"ts": "2024-11-08 09:00:00", "value": 78}]}`——**一个只有一条记录的数组**。

判据取到 `hits=[那个 list]`，`float(list)` 抛 TypeError，`_value_match` 返回 False，然后报：

```
亮度设定自 2024-11-08 装机以来一直是 78，中途未下调（候选值 [{'ts': '2024-11-08 09:00:00', 'value': 78}] 都不是 78）
```

**这句话的问题不是不准，是往错的方向指。**

读数的人看到"都不是 78"，第一反应是"模型编了个数"→ 去查 prompt、去换模型。但真相是：模型想表达"78 属于 2024-11-08 那条记录"，而 claim 只有一个 `value` 字段装不下这个配对——正确做法是改用 `items`。

而这件事**判据自己完全知道**：它手里就是数组、claim 就是单值。知道却不说，等于让读数的人替它归纳。

## 改法

在单值分支的值比较之前，先判一次结构：

```python
if hits and all(isinstance(g, (list, dict)) for g in hits):
    stats["path_bad"] += 1
    n = len(hits[0]) if isinstance(hits[0], list) else 1
    misquoted.append(
        f"{text}（ref 指向数组/结构：{tool}#{path} 返回 {n} 条记录，"
        f"单值 claim 装不下「哪条记录等于多少」。"
        f"这种配对请改用 items: [{{\"key\": \"<标识>\", \"value\": {v}}}])")
    continue
```

**判定不动**：仍记 `path_bad +1`。只换说法，不换判决——否则"改话术"就成了偷偷放宽的同义词。

`all(...)` 而不是 `any(...)`：只要候选里有一个标量，就说明这条 ref 曾经取到过可比较的值，仍按"值不对"判，不能把真错洗成结构问题。

## 验证

| 项 | 结果 |
|---|---|
| 单测 | **123/123**（新增 2 条：一条正例要求报 `items`、一条反向要求标量仍报"都不是 80"） |
| 判据夹具 | **10/10**（A4 的 `misquoted_has` 从 `"都不是 78"` 改为 `"指向数组"` + `"items"`） |
| 27 条离线重放 | `path_bad` 合计 **仍为 2**（与 `4175d0a` 基线一致）→ **零误伤** |
| 新分支命中 | **1 条**（A4 亮度）；A1 仍走原来的"候选值 0.1875 都不是 17.65%" |

## 边界

覆盖面很小——全量 27 条里只有 1 条。**这不是"改了没用"，而是这类问题在当前数据里本来就少。**

但它的读数成本原本最高：一句话说不清，人就得翻三个脚本才判断得出该改哪。判据的价值不只是判对错，还有**判完之后能不能让人立刻知道该改什么**。

## 同类问题还剩一处

`T2`（定性结论挂数组，没有数字的 claim 指向 records）——判据目前放过，但那是模型恰好没挂数组，不是结构修好了。要根治得让定性 claim 也有地方放"这句定性针对哪条记录"，属于结构设计，不是话术。
