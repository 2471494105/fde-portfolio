# 定性 claim 也要验 ref

`2026-11-18` · 对应提交 `8298397`

## 问题：一行 continue 让整类断言漏检

`_verify_claims` 里有这么一段：

```python
items = c.get("items")
has_items = isinstance(items, list) and bool(items)
if v is None and not has_items:
    continue          # 纯论述型 claim，既没数字也没引文，无从核对
```

注释写的理由是"无从核对"。但看仔细一点：`continue` 发生在 **ref 解析之前**。

所以模型写这条：

```json
{"text": "1 号工位是主要问题工位", "ref": "query_defect_log#groups[99]"}
```

判据**一句话都不说**。而 `groups[99]` 根本不存在。

**这不是"没法核"，是"没去核"。**

## 为什么定性 claim 反而更该验

数值 claim 有两个凭据：值对不对、ref 指不指得到。定性 claim 只有一个——**ref**。

"这句话说的是哪个工位、哪条记录、哪次标定"，全在 ref 里。ref 指不到，这句话就悬空了，没有任何东西能说明它依据什么。

所以逻辑上正好相反：**没有值可比的时候，ref 检查更重要，不是更不重要。**

## 改法：走完整路径检查，比值那步停下

```python
qual = (v is None and not has_items)
if not qual:
    stats["qty"] += 1
    if unit == "%":
        stats["pct"] += 1
```

`qual` 往下走 `_REF_PAT` 解析、工具名查找、指纹收窄、`_get_path` 取字段——和数值 claim 完全同一条路。然后在比值之前分叉：

```python
if qual:
    stats["qual_ok"] += 1
    stats["path_ok"] += 1
    continue
```

三种产出分开记，因为三种修法不同：

| 字段 | 含义 | 处理 |
|---|---|---|
| `qual_ok` | ref 指得到 | 站住，同时计入 `path_ok` |
| `qual_bad` | ref 指不到 | `misquoted` 判失败，**不混进 `path_miss`** |
| `qual_unsourced` | 没写出处 | `blocked` 标灰，不判死 |

两个刻意的选择：

- **计入 `path_ok`**：它的语义是"引用路径成立"。定性也在引用，只是没有值可比。不记进去，报告上"可追溯比例"就只覆盖数字那半截，定性是隐形的——和当初"标灰看不见"是同一个病。
- **`qual_bad` 不进 `path_miss`**：一个是"数字没出处"，一个是"结论没落点"。混在一起，看数字的人会以为模型在编数值。

## 判死与放行的边界

**判死的只有"写了 ref 但指不到"。**

没写出处的定性 claim 只加 `[无出处]` 标记。因为它提供了无法核验的断言，但**没说假话**——纯推理型 claim（"因此判断为光源老化"）本来就没有数据出处可写，判死会让这类推理根本没法写进 claims。

## 验证

| 项 | 结果 |
|---|---|
| 单测 | **126/126**（新增 3 条：坏 ref 要抓、好 ref 要过且不计入 `qty`、无 ref 标灰不判死） |
| 判据夹具 | **10/10**（夹具不断言 `path_ok`，计数变化不影响它） |
| 27 条重放 | `qty` 仍 **324**、`path_bad` 仍 **2**、`misquoted` 仍 **2** → **零误伤**；`qual_ok=2`、`qual_bad=0` |
| 真实样本注入 | 把 H2 那条定性 claim 的 ref 改成 `query_device_profile#station[9]` 和 `query_light_usage#no_such_field`，两次都 `qual_bad=1`、`path_miss=0` |

那条真实样本值得记一笔：H2 的定性 claim 是"最近一次标定在 2026-10-30，结果通过"，ref 是 `query_calibration#records[0].result`——**引的是一个字符串字段（"通过"）**。这正是定性 claim 的典型形态：用一个词概括一条记录的状态，没有数字可核，只有一个 ref 说"我从这儿看的"。

## 代价

未来模型写没出处的定性 claim 会被标灰，`final_text` 里多出 `[无出处]`。

这是刻意的：`claims` 数组里的每一条，都是模型自己声明"这条可以被核验"。可核验却不给出处，就该看得见。宁可输出多一行标记，也不要让断言悄悄滑过去。

## 覆盖面

27 条里只有 2 条定性 claim（H2、I2 各一），而且这两条 ref 都是对的。

**所以这次改动的收益是"关掉一条通道"，不是"修掉了两个错误"。** 当前数据里没人利用它——因为它根本不需要被利用就能通过。
