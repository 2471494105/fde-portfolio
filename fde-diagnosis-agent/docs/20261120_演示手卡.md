## 一、开场前 3 分钟（缺一步就会翻车）

## 二、三幕脚本（总耗时约 46 秒模型时间）

### 第一幕：完整诊断（22.5 s，5 步）

- 输入：`CX-101 误判率有点高，你看看怎么回事`
- 工具序列：`query_device_profile → query_defect_log → query_light_usage → query_calibration → check_doc_conflict`
- 可讲的三句：
  - 误判率 23.89%（27/113），1 号工位 58.82%（20/34），3 号工位仅 10.64%（5/47）——同一个厂里差异这么大，指向局部硬件而不是模型阈值；
  - 光源累计 8620 h、额定 8000 h，超寿命 620 h，亮度从 85 → 80 → 65 被两次下调；
  - 标定 2026-10-30 漂移 0.467px、结果通过，可排除标定漂移。
- 加分点：结论里主动写了"光源亮度设定存在文档冲突（手册 80 / 厂内 SOP 65），请质量确认以哪份为准，我不替你选"——这是 `check_doc_conflict` 的价值，也是"不确定就不编"的实证。

### 第二幕：设备不存在（7.5 s，2 步）

- 输入：`CX-106 这台设备最近误判有点多，帮我看看`
- 工具序列：`query_device_profile → query_defect_log`
- 可讲：台账只有 CX-101…CX-105，模型拒答并列出可选项，**不对不存在的设备做任何推断**。
- 注意有个坑：`query_defect_log` 对 CX-106 返回的是 `no_defect_log`（"设备确实没有误判日志，属于结论而非故障"），
  这句话本身容易误导——模型没有跟着它走，仍然以台账为准。这一条正好用来讲"工具会撒谎，结论要交叉验证"。

### 第三幕：带着模糊诉求建单（15.9 s，2 步）

- 输入：`3号线 CX-103 反正就是有问题，你先给我建个工单`
- 工具序列：`query_device_profile → create_work_order` → 库内出现 `WO-20261120-002`（待处理）
- 可讲：结论第一句就写明"CX-103 根因尚未确认，按用户要求先行派工"——**不拿建单冒充诊断结论**。
- 库侧佐证：`select order_id, device_id, status from work_orders` 会看到多出这张单。

## 六、录屏（2026-11-20 装好的）

前提：`winget install Gyan.FFmpeg`（本机已装 `ffmpeg 9.0.2`）。
采集走 `gdigrab`，编码 h264 + `yuv420p` + `+faststart`，Windows 播放器和手机都能直接播。

```powershell
# 默认：主屏、15 fps、120 s、输出到 docs\demo_recordings\demo_<时间戳>.mp4
powershell -ExecutionPolicy Bypass -File scripts\record_demo.ps1

# 只录浏览器窗口（最干净，标题按子串匹配）
... -WindowTitle "诊断"

# 双屏都要、或要更长时间
... -AllDisplays
... -Seconds 180 -Fps 20
```

脚本会先查两件事并给警告：mock QMS 8010 通不通、`work_orders` 是不是只剩 1 张。
**录制期间不要弹出聊天窗、终端以外的无关窗口**——全屏抓的是"人眼看到的样子"。

三个实测踩过的坑（都已修在脚本里，别再改回去）：

1. `-offset_x` / `-video_size` 必须写在 `-i desktop` **之前**；写在后面会被当成输出选项静默忽略，白设。
2. 这台机器是双屏（虚拟桌面 3840×1080，主屏在右侧 `0..1920`），gdigrab 的 offset 语义和
   `System.Windows.Forms` 报的坐标对不上，直接给 offset 会报 "extends outside window area"。
   最终改成**整块抓 + `crop` 裁主屏**，稳定。
3. PowerShell 里 `"crop=$($w):$($h):$x:$($y)"` 这种写法会被解析成空表达式（ffmpeg 报
   `Undefined constant ... in ''`），必须显式拼接字符串。

产物默认进 `docs\demo_recordings\`（已在 `.gitignore` 里，视频不入库）；
ffmpeg 的日志留在同名 `*.mp4.log`，出问题先看它。

## 七、怎么把三幕"演"出来（2026-11-20 12:47 成片后的结论）

驱动只走 Windows UI Automation，不用鼠标坐标。本机双屏，`cu` 坐标覆盖整块虚拟桌面（原点 −1920），
点 (578,300) 实际落在副屏；`bu` 也看不到这个 Edge 实例（`list_tabs()` 返回 `[]`）。
UIA 按控件名直取：`诊断`（Button，屏幕 rect 1379,350,75,44）、输入框（Edit，Name 以"例如："开头，rect 451,248,1003,87）、
`新会话`（Button，rect 1302,352,70,40）。填值用 `ValuePattern.SetValue`，提交用 `InvokePattern.Invoke`。

**每一幕之前必须先点"新会话"。** 同一会话会继承上一轮的设备范围：先问 CX-106、再问 CX-101，
会被"本轮会话的设备范围被限定为 CX-106，而 CX-101 不在授权范围内"直接拒答——白演一幕（12:35 那版就是这么废的）。

**1080 视口装不下整页。** 输入框 + 实时执行时间线就占满屏，`诊断结论`标题落在 y≈870–890，
正文全在折叠线以下；录制时不滚页面，观众看不到结论，只看到时间线。

滚动别用 `ScrollIntoView` 一把梭：它只把结论放到 y≈546，正文仍被切；`SetScrollPercent(…,100)` 更糟，
直接跳到最底下的"历史运行"列表。可用做法是**标定后按百分比逼近**：

1. 回顶记 y0（约 870–890），滚 5% 再记 y5，每 1% ≈ 19 px；
2. `SetScrollPercent(NoScroll, (y0 − 230) / pp)`，落点 y ≈ 226–229；
3. 这个落点下结论正文连同 20 多条引用数字全在一屏内，下方还露出"工具调用轨迹"，正好当证据讲。

成片：`docs\demo_recordings\demo_20261120_124708.mp4`（85 s / 1920×1080 / 20 fps / 1.9 MB）。
抽帧核验：30 s = 第一幕完整结论；60 s = 第三幕执行中；75 s = 建单结论（`WO-20261120-002 已创建`）+ 调用轨迹。
前面三版已删：12:35:10（第一幕被授权范围拒答）、12:38:40（第三幕被切在片尾）、12:43:35（第一、二幕滚动没跟上）。

录完记得重导种子：`psql … -f data\seed\002_data.sql`，`work_orders` 回到 1 张。

## 八、界面中文化（现场读得懂的那一版）

判据：**结论和执行过程里不出现英文枚举、不出现英文工具名**。原始串只留在折叠区，标明"工程核查用"。

| 位置 | 原来现场看到的 | 现在 |
|---|---|---|
| 执行时间线 | `意图：action` | `意图：执行动作（建单 / 派工）` |
| 执行时间线 | `决定调用 query_device_profile、query_defect_log` | `决定调用 查设备档案、查误判记录` |
| 执行时间线 | `query_calibration 已返回` | `查标定记录 已返回` |
| 轨迹标题 | `#1 query_device_profile` | `#1 查设备档案` |
| 轨迹参数 | `device_id=CX-101`、`group_by=station` | `设备编号 CX-101`、`分组维度 按工位` |
| 轨迹返回 | `{"device_id": "CX-101", "state": "found", …}` | 两列字段表：`设备编号 CX-101`、`查询状态 存在`、`保养周期 90 天`… 最多 12 行 |
| 轨迹列表 | 整串 JSON 数组 | `分组明细（共 3 条）` + `分组 1号工位 · 条数 34 · 其中误判 20 · 误判率 58.8%` |
| 结论正文 | 每条结论后面挂 `[query_defect_log{group_by=station,...}]` | `[查误判记录{分组维度=按工位、按缺陷类型、按批次、按天}]`、`[查光源使用]` |

八个工具的中文名：查设备档案 / 查误判记录 / 查标定记录 / 查光源使用 / 查手册 / 查文档冲突 / 查工单 / 建工单。

唯一**故意没翻**的地方：轨迹与返回里的折叠区 `原始 JSON（工程核查用）`——模型当时看到的就是这份文本，删了就没法回答"它到底读到了什么"。结论里的引用标签则由后端 `cite_text()` 只翻认得的工具名和参数名，认不出的一字不改（正文是证据，翻错比不翻更糟）。

读返回的取数口径：`evidence.result` 存的是带签名的整串 `[tool{args}] {json}`，不是对象；后端 `_as_obj` 先剥签名再 parse，`_view` 拿完整对象算字段表（前端拿到的 `head` 是截 600 字的残片，parse 必失败）。

刷新注意：`/` 已加 `Cache-Control: no-cache`。之前改完前端直接 F5 仍是旧页面，会误判"改没生效"。

滚动取景补一条：百分比标定在窗口换屏或内容更长时会失效——`SetScrollPercent` 到 95% 就夹住不动，落点还停在 y≈1228。**更稳的是回顶后用 `{PGDN}` 逐屏逼近**，看锚点元素 `BoundingRectangle.Y` 落在 80–210 就停（实测一格约 836 px，三屏到"工具调用轨迹"y≈219）。
