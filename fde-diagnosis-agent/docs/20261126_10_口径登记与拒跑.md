## 一、问题：一句话口径写了四份

`('已完成','已合并','已取消')` 这三个词，2026-11-26 之前是**四处源码 + 一处快照**：

| 位置 | 用它做什么 | 漏改的后果 |
|---|---|---|
| `data/schema.sql` `work_orders_open_key` | 部分唯一索引谓词：已闭环不占幂等键 | 索引按旧词判闭环：已关闭的单继续占键，同一问题处理完再坏，建不了新单 |
| `mock_qms/reset.py` 保护集反查 | 谁还占着幂等键（清空前先列出来） | 保护集与索引各按一套词判，清空计划与实际去重口径不一致 |
| `scripts/check_ds_delete.py` `OPEN_STATUS_EXCLUDE` | 谁不能被删（有未闭环引用） | 报告里写的 policy 与行为不一致；一处宽一处严会出现「建单能建、设备却被删」 |
| `scripts/check_data_contract.py` A3 | 同一幂等键只能有一张未关闭的单 | 断言查错词，永远 0 行——**绿得最像真的** |
| `eval/data_health.json` `policy` | 报告里的判定参数 | 报告引用的是上一版口径 |

四处互不校验，漏改不报错。这正是「字段错第一分钟就炸、口径错三个月都不炸」的那一类。

## 二、决定

1. **登记一处**：`data/mapping/status_policy.json`，每客户一份，`registered` 是显式开关（`client_a` 已登记，`client_b_odoo` 故意留 `false`）。
2. **未登记就拒跑**：`app/ds/status_policy.py` 抛 `PolicyNotRegistered`，不返回空词表。返回空元组会把「全部未闭环」当结论，这是最坏的一种猜法。
3. **索引谓词是唯一例外**：部分索引的谓词必须是不可变表达式，读 JSON 的函数不满足 `immutable`，PostgreSQL 会拒绝建索引。所以它继续写三词，由 A 判据盯漂移（`schema.sql` 里已就地注明原因）。
4. **词以参数进 SQL**：`open_predicate()` 返回 `(片段, 参数)`，片段是 `status <> ALL(%s::text[])`，词不拼字符串——否则调用点又变成一份手抄。
5. **报告带版本**：`policy_summary()` 输出 `version / client / registered / clients`，`check_ds_delete.py` 的 `policy()` 把它嵌进 `data_health.json`，报告要能回答「这份绿按哪版口径判的」。

## 四、取舍：为什么不做那几种更省事的写法

| 没做 | 理由 |
|---|---|
| 未登记时猜一个默认词表 | 猜错不报错，保护集只增不减，删除功能等于没有——**症状与正常一模一样** |
| 建一张跨客户状态词典（Odoo `state` ↔ 我们的三词） | OPC UA 把状态机定义成封闭集合（子类型不得增删 States/Transitions），换客户等于换一版契约；跨公司映射没有大厂公开规范，折/拒/丢的判定是本项目推论，不能包装成标准 |
| 加 `--allow-unregistered` 开关 | 它就等于「先让它跑起来，以后再收紧」，而这个错恰好不报错；要放宽时应该改登记，不是关闸 |
| 把索引谓词改成读 JSON | PostgreSQL 不建索引。能做的只有「留字面量 + 一条判据」 |
| 用视图替代部分唯一索引 | 视图不带唯一性，去重保证会消失——这是把约束降级成约定 |

## 六、未做

- **K-5 仍未测**：这一步只把「未登记」变成显式拒跑，没有证明折法本身正确（两家客户真实口径打架的场景仍未跑）。
- `open_predicate` 目前只有黑名单分支；客户若给正向白名单（`state: confirm`），要在登记里加 `open_states` 分支并配判据。
- 索引谓词仍是字面量，改口径需要 `DROP INDEX` + `CREATE INDEX` 的迁移脚本，没写。
- `eval/data_health.json` 里那份 `policy` 快照尚未重跑刷新——下一次巡检会自然带上 `status_policy` 与 `version`。
