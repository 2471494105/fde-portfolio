# 值域抽查（S5）：列名没变，值的意思变了（DOC-54）

> 2026-11-26。卡 2 的第二个判据层。第一层（S1–S4，登记与漂移）在 `DOC-53`。

## 一、S1 看得见什么，看不见什么

`DOC-53` 的 S1 比的是**列的集合与类型**。源端把 `conf_pct` 从百分制（91）改成小数（0.91），列名一样、类型一样（都是数值），S1 全绿——而 `app/ds/mapping.py` 的 `scale` 照乘 0.01，91 变 0.91 那一版会变成 0.0091。**不报错，只是从此所有置信度都不对。**

`DOC-53` 第七节里那句「只改数据不改 schema 的变更，这一层看不见，得上值域抽查，**没做**」，就是这一篇要补的口子。

## 二、五类变更与三档处置

| 变更 | 判定依据 | 档 |
|---|---|---|
| 量纲缩小 100 倍（百分制→小数） | 声明 `[0,100]`，观测 `max ≤ 1` | **拒跑**（exit 3） |
| 量纲放大 100 倍 | 声明 `[0,100]`，观测 `min ≥ 1000` | **拒跑** |
| 日期格式整体改（`2025/03/12` → `2025-03-12`） | 声明格式全不匹配，却能 100% 按另一常见格式解析 | **拒跑** |
| 值全部不可解析 | 声明的 range/format 一个都不成立 | **拒跑** |
| 超范围 / 部分行不符合格式 | 只有一部分值越界/不合格式 | 红（exit 1） |
| 枚举扩值 | 出现词表外的值 | 黄（exit 0，列出来） |
| 空值（声明允许 / 不允许） | 空值计数 | 记 / 黄 |

分档的理由只有一条：**量纲与格式是基准，基准变了乘出来的每个数都错；越界可能只是新数据边界，人和数据本身能判断。**

## 三、声明写在哪

写在源端登记同一份文件里（`data/mapping/source_schema/<client>_<table>.json` 的 `domains`），不另起一份——「这一列叫什么」和「这一列的值是什么形状」是同一个问题的两半。

```json
"domains": {
  "conf_pct": {"unit": "percent", "range": [0, 100], "range_severity": "yellow",
               "note": "真实样本第 5、6 行是 150 与 -10，属隔离区夹具……"},
  "captured_at": {"format": "%Y/%m/%d %H:%M"},
  "judge": {"enum": ["NG", "OK"]},
  "is_ok": {"enum": ["N", "Y"]}
}
```

两份登记的声明都是**从观测值读出来的**，不是套通用格式：

- `devices`：`maint_cycle` 天数 `[1,3650]`、`install_dt` 是 `%Y/%m/%d`（**斜杠**，不是短横）、`equip_no` 允许空（真样本第一行就是空的）；
- `defect_logs`：`conf_pct` 百分制 `[0,100]`、`captured_at` 是 `%Y/%m/%d %H:%M`、`judge ∈ {NG, OK}`、`is_ok ∈ {N, Y}`。

`judge` 的枚举是脚本读了全部 10 行之后写进去的（`NG/OK`），没有手填——手填容易写成 `OK/NG/REVIEW` 这种「应该有的样子」。

## 四、实测

真实样本（`check_source_values.py`，默认抽前 200 行）：

```
[warn] client_a/defect_logs  rows=10  列=['captured_at','conf_pct','is_ok','judge']
        S5 黄 conf_pct：2/10 个值超出声明 [0,100]  样本 [150.0, -10.0]
[warn] client_a/devices  rows=5  列=['equip_no','install_dt','maint_cycle']
        S5 记 equip_no：空值 1/5（声明允许空）
```

两条都能追到具体行：`conf_pct` 的 150 与 -10 是第 5、6 行，属**隔离区夹具**（`check_data_contract` 需要它们触发断言），不是源端口径变化——所以这一列在登记里写 `range_severity: yellow` 并注明原因；**整列量纲真变了（全列 ≤ 1）仍然判拒跑**，两条规则不冲突。`equip_no` 的空值是第 1 行，登记为允许空，所以只记不红。

四个反例（`--source=` 指向临时 CSV，不动真样本）：

| 反例 | 做法 | 结果 |
|---|---|---|
| 百分制→小数 | `conf_pct` 全写成 `0.91/0.88` | `S5 拒跑 conf_pct：量纲疑似缩小 100 倍`，exit **3** |
| 枚举扩值 | `judge` 写 `RECHECK` | `S5 黄 judge：出现词表外的值 ['RECHECK']`，exit **0** |
| 日期格式整体改 | `install_dt` 全写成 `2025-03-12` | `S5 拒跑 install_dt：实际全都能按 %Y-%m-%d 解析`，exit **3** |
| 部分行缺时间 | 一行 `2026/11/02`（无时分） | `S5 captured_at：1/2 个值不符合`，exit **1** |

规模与代价：新增 `tests/test_value_domain.py` **19 条**，全量单测 489 → **508**；`code_hash` 仍 `b5b70ab771e6`、`seed_hash` 仍 `9caa1322fbfc`（`app/ds/*`、`scripts/*`、`data/mapping/*` 都不在 `BEHAVIOR_FILES`，**没付 373 s**）；快照 `eval/source_values.json`。

## 五、三个决定，其中一个是被真数据逼出来的

1. **没声明 `range` 就不查数值。** 第一版 `check_range` 无条件比数值，跑真数据把 `install_dt`（日期）、`equip_no`、`judge`、`is_ok` 全判成「不是数值」——4 条假红。改成「声明了 range 才走这条」，并留了一条单测钉住（`test_no_range_declared_means_no_check`）。这是**判据自己制造的假红**，不是数据问题。
2. **越界默认红，但允许登记里降成黄。** 降级必须写理由（`note` 字段），否则下一个人看不出为什么这条可以黄。当前只有 `conf_pct` 用了降级，理由是夹具。
3. **默认只抽前 200 行，且输出里写清楚。** 全表扫在大源上不现实；抽样就必须承认是抽样，不许让「抽了 200 行没发现」读成「全表没问题」。

## 六、没做的事

- **只覆盖了 ×100 / ÷100 的量纲跳变。** `mm → cm`（×10）、`秒 → 毫秒`（×1000）这类型抓不到，得靠 `unit` 字段人工比对。`unit` 现在只声明不判定。
- **跨列一致性没判。** 真样本里 `equip_no` 同时有小写 `cx-101`、大写 `CX-101`、还有第 1 行空值——这是真实的口径问题（大小写是否同一台），S5 不管，归口径表。
- **格式类只覆盖日期。** `lot_no`（批号）这类编号格式（真样本里有 `A`、空、`B20261101` 三种）没有声明，也没有判据。
- **抽样不是全表。** 见第五节第 3 条。
- **`eval/data_health.json` 未接这一层。** 与 `DOC-52` 的 `policy` 快照、`DOC-53` 一样，等下一次巡检自然接。
