# 量纲判据改看中位数：一个脏值不该掩盖整列换基准（DOC-56）

> 2026-11-26。`DOC-55` 第六节记下的脆点，这一篇修掉。代码提交 `8fc672f`。

## 一、旧规则的形状与它的空洞

旧判据拿**极值**当量纲证据：÷100 判 `max ≤ hi/100`，×100 判 `min ≥ hi*10`。

空洞在于：量纲是**整列**现象，极值却是**单点**现象。库里躺一个 `150`，÷100 之后变成 `1.5`，`max ≤ 1` 立刻不成立——一次真实的百分制→小数切换，就这样被一个脏值洗成"只是超范围"：判据沉默、数据在库、结论是绿的。

这不是推演出来的。`DOC-55` 的 e8 第一版就是撞上它才改成"取 `conf_pct between 0 and 100` 的干净子集"——**当时是靠改样本绕过了改判据**。绕开能跑绿，但真实客户库里那个 150 不会自己消失。

## 二、为什么是中位数，而不是比例或分位数

先试了"支持率 ≥90%"：先取声明区间内的值，再看其中有多少落在 `(0, hi/100]`。结果被自己的实测否掉——9 行样本里 1 个脏值就占 11%，`88.9% < 90%`，直接不触发。

这件事的性质不是"阈值调小一点"：**按比例判，样本越小越容易被单点掀翻**，而客户首次接入恰好都是小样本（这次 e8 的探针本身就是 11 行跳成 20 行）。换个阈值只是把小样本的破点挪个位置。

中位数不需要阈值：

- 整列缩放 `c` 倍，中位数也正好缩放 `c` 倍（这是尺度的性质，不是统计技巧）；
- 单点脏值挪不动中位数，除非脏值超过一半——**超过一半就不再是"同一基准下的脏值"，而是分布变了**；
- 用一句话就能对外解释："整列缩了 100 倍，中位数也该缩 100 倍"。判据的可解释性优先于统计上的精致——复核判据的人不该需要复现一个分位数算法。

## 三、新口径

| 判定 | 证据 | 档 |
|---|---|---|
| 缩小 100 倍 | 声明区间内（`lo ≤ v ≤ hi`）的**中位数**落在 `(0, hi/100]` | 拒跑 exit 3 |
| 放大 100 倍 | **全部值的中位数** ≥ `hi*10` | 拒跑 exit 3 |
| 超出范围 | 越界值个数与样本 | 按登记档位（本例黄） |

三条附带决定：

1. **判定不再 `return`**。旧写法量纲 breaking 立刻返回，于是"150 越界"这条被吞掉；现在两条一起报——一种问题不许吞掉另一种。
2. **不加最小样本护栏**。n=1 时中位数就是该值本身，与旧写法同风险面；加护栏等于悄悄放宽，还会让 e8 的两行样本直接失效。
3. **`in_range` 为空则跳过缩小判定**。全是越界值时，"越界"已经把话说完了，不必再猜量纲。

## 四、成对的反例：少一个就是把自由度放开了

| 证据 | 造法 | 期望 | 必须有它的理由 |
|---|---|---|---|
| **e8** 带脏值 ÷100 | 客户库前 20 行**原样**拿（含 `150` / `-10`），只把 `conf_pct` ÷100 | exit 3，报量纲，同时报超范围 | 证明脏值不再掩盖真实跳变 |
| **e9** 带脏值不缩放 | 同样 20 行，一个数不改 | exit 0，不含"量纲疑似"，仍报超范围 | 证明脏值本身不是量纲证据，否则每次同步都误拦 |

只改 e8 不改 e9，等于把"量纲判据"改成了"越界就拒跑"——那是另一个错误，而且更吵。

## 六、这个修法没有解决的

1. **只认 ×100 / ÷100**。mm→cm（×10）、秒→毫秒（×1000）仍抓不到。推广成"中位数比值落在常见量纲表里"能救，但那就从"判据"变成"猜测"，没做。
2. **假设整列同一个基准**。同一列里一半百分制、一半小数，中位数会落在中间，判定沉默——不误报，也不报告。这属于跨行一致性，需要另一条判据。
3. **声明写错时判据跟着错**。[0,1] 误写成 [0,100]，会天天拒跑。登记的可信度仍是前提，判据不兜。
4. **抽样仍是前 200 行**。如果量纲变化只发生在新数据（前 200 行全是历史），中位数看不见。
5. **e9 只证明 1–2 个脏值不误报**。10% 以上都越界时中位数会被推移，那时"整列变基准"与"大量脏值"分不清——当前按前者处理（拒跑）。这条代价与 `DOC-55` 第八节同源，没有变好也没有变坏。
