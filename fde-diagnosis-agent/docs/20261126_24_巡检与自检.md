# DOC-66 · 巡检自检：让「页面上的数字是现在的吗」可被回答

> T24 / 2026-11-26 / 一条命令 `scripts/patrol.py`

## 一、中控台自己也会静默

T23 把判据红变成了事件，但留了一个洞：**事件是扫描生成的，扫描本身没有记录**。

页面显示「未处理 2 · 违约行 367」，却答不出这组数字是五分钟前还是上周。判据静默有 KPI，扫描静默没有——这就是「监控自己的监控」缺失。`DOC-63` 已经把这条写进原则（监控自己静默比数据静默更危险），T24 把它落到事件链路上。

## 二、四件事

**1. 扫描写进同一张运行台账。** `raise_alerts.py` 每次真扫完落一行 `check_id = alert_sweep`，`red_count` 口径是**本次新增推送条数**（`details.red_metric = pushed_events`），不是违约行数。两种量不混成一个数，否则趋势线又会失去意义。`--dry-run` / `--list` / `--ack` 不写。

**2. 页面报「扫描多久前」，并在静默时红出来。** 第三张卡改成「事件扫描」，值取扫描年龄；超过 24 h 或从没扫过 → 卡片转红 + 顶部横幅写明恢复命令。页面不自己判断阈值，阈值仍由 `/v1/obs/runs` 给。

**3. 一条命令跑完巡检。** `scripts/patrol.py` 按固定顺序跑：工位判据 → 口径判据 → 缺陷判据 → 事件扫描。退出码只有三种：0 无事、1 有新增要处理、2 有环节崩了（**崩了不许当红也不许当绿**）。

**4. 顺手补两个「答不出来」的小口子。**

- `/v1/obs/api` 增 `errors_by_path`：以前只有一个 `errors: 31`，答不出哪条接口在坏；
- `obs.record` 跳过 `/favicon.ico`：浏览器自己来要的 404 不是接口故障，混进错误率会让人去查一条不存在的路（本轮截图里就出现过 `最多 /favicon.ico 1`）。

## 四、没做什么

- **没有定时调度**：`patrol.py` 仍是「有人跑」；写进计划任务/CI 才是无人值守，这一步没做（与「先有告警没有处理人比没有更糟」同一条边界）；
- **阈值仍是全局 24 h**：没按客户/表分开，仍是拍的；
- **没有升级链**：扫描静默只红在页面上，不会自己去找人；
- **扫描只覆盖事件层**：`patrol.py` 跑的是现有三道判据，S1–S5、搬数、事实层巡检不在里面；
- **自检行与判据行共用一张表**：`red_count` 口径不同，靠 `details.red_metric` 区分；查询时若不分口径会误读。

## 五、答辩三问

**问：为什么把扫描写进判据台账，不单独建一张表？**
答：因为要回答的是同一个问题——「这件事发生过吗、多久以前」。单独建表会多一套查询和一套阈值；用同一张表 + `red_metric` 区分口径，页面一次 `/v1/obs/runs` 就够。

**问：为什么用一条 Python 命令，不用 Airflow / cron？**
答：顺序是这段业务的一部分（先判据后事件），写成代码比写成调度配置更不容易错；等有无人值守需求再接调度器，`patrol.py` 就是那个可被调度的原子。

**问：为什么扫描静默用横幅，不只在卡片上标红？**
答：红卡只说「这个数不对」，横幅要给出**下一步做什么**（跑哪条命令）。告警不给动作，就只是换个地方报错。
