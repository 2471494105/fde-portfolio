## 一、这一屏答什么

上一轮中控台能说出「40 行没有闭环」，客户下一句一定是：

1. **哪 40 行？**
2. **长什么样？**（值是不是真的空、是不是真的 150）
3. **我改哪一栏、改成什么？**

这三问答不上，事件就只是噪音——喊了一声「你有问题」，然后让人自己去找。这一轮补的就是这三问：中控台每条事件标题都能点，点进去是 `/problem?alert=<编号>`，一屏里给出**具体行**、**原样值**、**指引**。

## 二、事件 → 目标数据：三条链，一环都不能省

| 环节 | 存在哪 | 谁写 | 为什么不能省 |
|---|---|---|---|
| 行编号 | `gov_check_run.details.ids` | 判据跑完时 | 事件 `detail` 只存 `run_id` 与统计数；编号放在台账里，事件只做指针 |
| 编号 → 表 | `gov_issue_catalog.targets`（jsonb） | `seed_issues.py` | 页面不认得 `alarm:` 是什么；映射只有一份（Python 源在 `app/ds/issues.py`） |
| 行 → 片段 | 目标表主键回查 | `api/problems.py` | **只按编号回查，不重算判据**——两套口径对不上账时，客户不知道该信谁 |

编号格式（这一版三种，都写进明细页的「定位列」）：

- 归属类：`wo_station_identity#WO-2026-0001`、`defect_station_identity#<rec_id>` → 砍前缀取键；
- 字段类：裸 `rec_id`（`4/5/6/8/10`），目标表登记 `bare=true` 才认——没有前缀就是它自己的键；
- 报警类：`alarm:<alarm_id>`。

## 三、新判据 L：报警有没有人接

`scripts/check_alarm_ack.py`。为什么现在补：前三类都在说「数据填得对不对」，客户真正会指着屏幕讲的另一件事是「这条报警挂了三天没人管」。`biz_alarm` 120 行里 **40 行 `acked_by` 与 `cleared_at` 同时为空**——不是脏数据，是流程没闭环，而且这张表连 `station_id` 都没有，拿归属类去套只会得出「没法判」。

口径：两列分开记（`acked_missing` / `cleared_missing`），按 `alarm_id` 去重计行（`red_metric=violating_rows`）。实测 40/40/40（同一批）。

## 四、口径更正：外部自检撤出客户事件流

上一轮把 `data_contract`（跑在 **fde_sandbox**）与 `source_values`（跑在 **client_a 的 CSV**）接成了客户库事件 #6/#7。客户点进去会发现那条脏行根本不在自己库里——这是**我这边口径错了**，不是数据修好了。

这一轮的处置：

1. `issues.py` 给三类打 `scope="external"`（隔离区、值域、结构）；
2. `raise_alerts.plan` 遇到 external **不进事件、只留台账**，并把历史红事件关掉，关闭理由写「口径更正」；
3. 中控台目录里这三行标「外部」标签，明细列显示「外部自检」（不是点不进去的假链接）；
4. KPI 口径改成**客户库 3 / 6 类**，外部 3 类单独写在 note 里——分子分母都不混。

结果：事件从 4 条回到 3 条（红 3 / 黄 0），违约行 362+5+0+**40** = 407。

## 五、页面四处改动

1. `/problem?alert=N`：事件头（红/黄、类别、责任方、轮次、台账 run）→ 「先做这一步」→ 判据怎么判的 / 备注 → 每张目标表一块（定位列、这轮几行、**改哪一栏**、行表、每行「打开 #键」跳到 `/v1/<集合>?q=<键>`）。
2. 中控台事件流：标题变链接（C11 验收「链接数 = 事件数」）。
3. 目录新增「明细」列：有活事件的类别显示「N 行 →」，0 样本显示 `—`，外部显示「外部自检」。**没有活事件就不给链接**——明细页答的是「这条事件点了哪几行」，凭空造一条会让人以为库里真有。
4. 空值显示：`acked_by` / `cleared_at` 为空时表格写灰斜体「空」，不补 0、不补 `—`（补 0 是这批数据最典型的一种谎）。

## 六、60 秒话术

> 「这条报警说 40 条没闭环。点进去——40 行一张表，`acked_by`、`cleared_at` 两列全空，编号 3、6、9… 就是这 40 条。上面一行写着改哪一栏：认领写 `acked_by`，处理完写 `cleared_at`。您要的是这个，不是我再讲一遍规则。」

**别说过头三句**：

- 不说「系统已经帮您分好优先级」——明细页只排序号，优先级要值班人定；
- 不说「点进去就能改」——页面是只读的，改数据走客户自己的 MES；
- 不说「外部那三类也是您的数据」——那是判据的靶子，撤出事件流就是为了不混淆。

## 八、没做什么

- 明细页不分页交互（只按 `size` 截前 50，行表脚注写「本页」）；362 行要靠 URL 加 `size`；
- 报警类**没有作业页**（`/v1/alarms` 只有只读 JSON），客户手上没有改报警的界面——这是客户侧 MES 的事，不在这套 demo 里；
- 不做「点行高亮/定位到页面某一行」：`/app/` 三页没有按编号定位的能力，硬做会变成假链接；
- 不做外部自检的明细（沙箱库行不在客户库，页面上点了也是空表，属于故意不给）。

## 九、答辩三问

**问：为什么不直接在页面上重新判一遍，还要回查？**
答：判据有 5 道、判据时刻还要注入（`--now`），页面再判一次就有两套口径。台账里的编号是「当时那一轮判出来的」，事件说 5 行就必须是那 5 行；重判会让「复跑后消失 1 行」变成「页面自己改口」。

**问：为什么报警类要和归属类分成两类？**
答：修复动作不同。归属类是「补 `prod_line`」，报警类是「写 `acked_by` / `cleared_at`」；混成一类，责任方、首步、指标单位都会打架（一个是行数归属，一个是闭环率）。

**问：外部自检既然有用，为什么要撤出事件流？**
答：因为它红的不是客户的库。放在事件流里，客户第一次点进去就发现「这行不在我库里」，之后你说的每一句话他都会打折。留在台账、留在目录的「外部」标签里，才既保住了自检证据，又不冒充客户的问题。
