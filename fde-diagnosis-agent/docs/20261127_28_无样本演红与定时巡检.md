# DOC-70 · 无样本的两类怎么演红，以及巡检怎么自己跑起来

## 一、这一篇答哪两个追问

答辩现场（或客户第一次看页面）最容易问的两句：

1. 「9 类问题，你都有样本吗？」——今天 `source_schema`（结构漂移）页面写「未跑」，`status_policy` 的 B 项（库里出现未登记状态）全绿。
2. 「判据谁在跑？现在是你在跑，明天你不在呢？」

第一句的错误答案有两种：硬说「都覆盖了」；或者老实说「没有样本」，然后被追一句「那它到底会不会红」。
第二句的错误答案是「有巡检脚本」，因为脚本在仓库里不等于在跑。

这一轮只做这两件事：**把「没有样本」换成「可以当场演红」，把「脚本存在」换成「计划任务在跑」**，
两件都留下可机器复跑的验收，不靠嘴说。

## 二、结构漂移为什么一直显示「未跑」

不是判据做不到，是它**从来没有落台账**：

| 项 | 原来 | 现在 |
|---|---|---|
| 写不写 `gov_check_run` | 不写（只打终端） | 写，`check_id=source_schema` |
| 进不进 `patrol.py` | 不进（巡检 5 道） | 进（巡检 6 道） |
| 页面「今日样本」 | `未跑` | 跑过后的真实数（今天 `0`） |
| 红的口径 | 只有 exit code | `red_count` = **漂移项数**（一表一项），`details.red_metric=drift_items` |

理由一句话：**判据没有台账，在中控台上就等于不存在**，跟它红不红无关。
这也解释了 T26 那轮为什么「目录里 8 类、事件只有 2 条」——不是判据少，是没接线。

## 三、`probe_red.py`：两个临时观测面，把两类当场演红

| case | 临时对象 | 动的判据 | 期望红法 |
|---|---|---|---|
| `source_schema` | 临时 CSV（改一列名 + 加一列），走 `--source=` | S1 增/删列 + S4 疑似改名 | `exit=1`，四行明细逐项点名 |
| `status_policy` | `fde_sandbox` 临时表 `probe_wo_bad`（3 行，1 行「完成待确认」未登记），只调 B 项函数 | B 未登记状态 | `status=fail`，`unknown_states=['完成待确认']` |

三条硬规矩写在脚本里：

- **不碰客户库**：一处是临时文件，一处只落在 sandbox；客户库工单整表指纹 `e21014390743de1f23f78ae2f188e654` 演练前后逐字相同（脚本自己比）。
- **反例不红就是失败**：判据没红说明判据失效，脚本 `exit 1`，不许说「演示成功」。
- **跑完必删**：临时 CSV `unlink`、临时表 `DROP`，并回查 `to_regclass` 确认真的没了。

```

    S1 新增列 ['we_added_this', 'work_station_renamed']
```

## 四、巡检为什么会撞车，锁怎么让路

计划任务每 30 分钟一次，人还可能手动跑一次。两次同时跑会有两个后果：写两行台账；`seen_count` 一轮推两次，「多久没人动」失真。

`patrol.py` 加了单实例锁：

- 锁文件 `logs/patrol.lock`，内容是 `pid=` 与时间；
- 撞车时后来的那个打一行并 `exit 75`（**75 不是错误码语义，是「让路」**，计划任务里看到 75 不用报警）；
- 超过 `--lock-ttl=900` 秒视为上一位已经崩了，允许抢——不许因为一次崩溃就永久不再巡检。

## 五、定时巡检怎么挂（两层，缺一层就是没人跑）

| 层 | 内容 | 为什么不能省 |
|---|---|---|
| 入口 | `scripts/patrol_hourly.py` | 一次只跑 `patrol.py --quiet`、日志按天落盘（UTF-8）、退出码原样带出 |
| 调度 | Windows 计划任务 `FDE-Patrol`，每 30 分钟 | 生产是 `crontab` / K8s `CronJob`，入口脚本通用 |

**踩坑写在这里**：先用 `.ps1` 做壳，日志全是乱码——python 按 UTF-8 写（`-X utf8`），Windows PowerShell 5.1 的重定向按控制台代码页（GBK）解码，再按 UTF-8 存盘，两头各错一次。日志看不懂就等于没有日志，所以壳改成 python 自己写文件，编码只有一种。

实测（本机，2026-11-27 11:10）：

```
LastRun=11/27/2026 11:10:10  LastResult=0  Next=11/27/2026 11:40:40
[2026-11-27 11:10:20] 结束 exit=0
巡检完成：判据 6 道 · 事件扫描 无新增 · 中控台 …/console 已可看
```

## 八、没做什么

- **没有真实推送凭据**：`raise_alerts.py` 早就支持 `--webhook= --channel=feishu|dingtalk`，这条命令里没出现任何地址，所以一直落投递箱；要真发，得客户/你自己给一个群机器人 URL（这是授权问题，不是能力问题）。
- 计划任务只在**开机且已登录**时跑；休眠不跑；没有失败重试与告警升级（红了推一次，不催办）。
- 没有值班表、没有升级链、没有「超过 N 小时未认领自动升级」——这三条要动报警作业页，属冻结项。
- 口径类只演了 B 项（未登记状态）；A/C/D/E/F/G/H 本来就有机器反例，没在这一轮重演。
- 页面上的趋势线**没变多**：新增 `source_schema` 只进台账，六条线只画行类判据——这是刻意的，行类和列类混在一条纵轴上，客户会以为「1 个字段越界」和「362 行归属」是同一个量。

## 九、答辩三问

- 「这两类没样本，是不是没做？」→ 不是，能当场演红：一列改名 + 一个未登记的词，两条命令，客户库指纹不变。
- 「这是真数据出的问题，还是你造的？」→ 造的，且只在临时对象上造；我不拿临时表当客户案例，它只证明**判据会红**。
- 「判据自己在跑吗？」→ 每 30 分钟一次，日志按天，页面上的扫描时间就是证据；休眠不跑这一点我直接说，不装成 7×24。
