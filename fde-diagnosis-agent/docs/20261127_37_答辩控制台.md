# 答辩控制台：8021 上的一个新窗口，四个按钮（T39）

- 日期：2026-11-27
- 状态：已完成并实测（文档编号 `DOC-79`）
- 涉及：`mock-mes/api/demo.py`、`mock-mes/api/static/demo.html`、`mock-mes/api/app.py`（4 条路由）、`mock-mes/scripts/verify_demo.py`（D1–D8）
- 一句话：**现场不敲命令、不记参数——点一下跑巡检、点一下演红；但它只是脚手架，8021 的读面仍是 `ro_reader`。**

## 一、为什么加这一页

现场只有一个人、一块屏。原来要记三件事：计划任务叫 `FDE-Patrol`、演红是 `probe_red.py`、收口是 `demo_closeout.py`（还要记住它写台账、会动 361/362）。忘一个参数就是一次当场卡壳，而且敲命令行本身在投屏上也不好看。

所以这一页的目标只有一个：**把「已有脚本」变成可点的按钮，别的什么都不改**。

## 二、为什么放在 8021，以及边界怎么守住

放在 8021 是因为现场少一个端口就少一次「打不开」。代价是 8021 从此多了一个**执行面**，所以守四条：

1. **它自己不写库**。`demo.py` 里没有一条写 SQL（`verify_demo.py` D6b 用正则断言）；按钮只是 `subprocess.Popen` 调 `fde-diagnosis-agent/scripts/*`，那些脚本用自己 `.env` 里的账号。8021 的读路径仍是 `ro_reader`（D6a）。
2. **只给本机**。非 `127.0.0.1` / `::1` 直接 403；`FDE_DEMO_OFF=1` 整页关掉——客户环境不该带这一页（D4a/D4b）。
3. **动作白名单**。四个动作写死在 `ACTIONS` 里，别的一律 404，不做「输入任意命令」那种后门（D2）。
4. **一次只跑一个**。独占槽，第二次点回 409 而不是排队——现场双击不会把同一件事演两遍（D3）。

## 三、四个按钮

| 按钮 | 跑什么 | 会改什么 | 什么时候点 |
|---|---|---|---|
| 开始巡检 | `patrol_hourly.py`（**与计划任务同一个入口**） | 写台账、可能推群；不改业务数据 | 开场第一件事：证明「它是真在跑」 |
| 演红 | `probe_red.py`（临时表头 + sandbox 临时表，跑完自删） | 不碰客户库 | 客户问「它红过吗」时 |
| 收口彩排 | `demo_closeout.py`（认领 → 补一行 362→361 → 复原） | 会动工单行数并复原；台账多两行 | 讲完整闭环时 |
| 生成处置清单 | `export_actions.py` | 只读 + 写 CSV，不写回客户字段 | 讲「带得走」时 |

页面上三盏灯：在开事件数、最近一次巡检（时间 + `ok/fail`）、当前动作（跑没跑完、exit 多少）。日志实时续读（`/demo/api/log?since=`），不是转圈等结果。

## 五、刻意没做的

1. **不做「输入任意命令」**：那等于给浏览器一个 shell。白名单是这一页存在的代价，也是它能存在的理由。
2. **不做真实鉴权体系**：只有 loopback + 可选 `FDE_DEMO_TOKEN`。真要多人的话是另一套设计（登录、审计、权限分级），不是答辩要的东西。
3. **不做队列**：409 拒绝比排队诚实——人看到「上一次还没跑完」，比看到「排队中」然后忘了点第二次更清楚。
4. **不把动作拆得更细**（例如「只跑第 3 道判据」）：演示讲的是「八道一起跑」，拆细反而把 8 这个数字讲乱。

## 六、局限（写清，别藏）

- **8021 从此有两个面孔**：只读展示 + 本机执行。交付给客户时要 `FDE_DEMO_OFF=1`，并且这句话得写进部署清单；不然「治理系统自己会跑脚本」这件事会被当成功能。
- **日志落在 `mock-mes/out/demo/`**，不进仓库（同 `out/actions/`、`out/backup/`）。
- **收口彩排会留痕**：每次点都写两行台账、动一次 361/362。彩排完对现场手卡的数字要再核一眼。
- **演红 exit 1 不是失败**：`probe_red.py` 判据没红就 exit 1——那是判据失效，页面上会显示红色 exit，别当成「按钮坏了」。
- **超时 240s 强杀**：收口彩排含无头截图，机器慢时可能顶到上限；真遇到就看日志末尾停在哪一段。
