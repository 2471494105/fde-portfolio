## 一、先把 407 拆开

| 判据 | 违约行 | 判的是什么 | 口径确认状态 |
|---|---|---|---|
| `station_contract` | **362** | 工单 / 缺陷的工位字段能对上主数据 | **未确认**（确认单 Q1） |
| `defect_fields` | **5** | 缺陷记录值域越界、空批次、未来日期 | 成立，不需要口径 |

| 合计 | **407** | | |

**所以对外不能说「发现 407 个错误」。** 准确说法是：

> 407 行违约，其中 **5 行不需要任何业务口径就能成立**；**402 行取决于两条客户还没确认的口径**（工位该存全码还是序号、三级报警要不要认领）。

这句话比「407」好听得多，也更难被问倒。客户一旦选了另一条口径，我们当天就能撤，而不是被指出来才改。

另外，**9 条时间倒置不在 407 里**——它还没落成判据，所以既不重复计数，也不影响演示数字。

## 四、未覆盖清单（明说不判）

| 不判的东西 | 原因 | 现在怎么交代 |
|---|---|---|
| 工单 `station_no` ↔ 主数据工位的跨表 join | 两套叫法，字面 join 会造 60 条假红 | 已登记在 `ref_integrity` 的 `not_compared`，附原因 |
| 缺陷 `lot_no` ↔ 检验批 | 没有检验批主表 | 同上；另在确认单 Q6 问口径 |
| 「这条记录本身对不对」（那次检验真的发生过吗） | 判据只能证明引用存在、值在范围内，证不了业务事实 | 写在口径页与限制清单里 |
| 报警「认领是否及时」 | 没有 SLA 定义 | 只判「填没填」，不判「快不快」 |
| 缺陷名侧别是否合规 | 没有标准字典 | 只提示，不判错 |

**这一节的用法**：面试或评审被问「那你们到底能不能发现语义错误」时，先答这一节，再答第二节——先划边界的人，比先报数字的人可信。

## 五、边界：这一轮不动后端

- 不新增判据、不改 407、不动事件 3 条、不动 8 道巡检。
- 理由：**加判据关不掉口径**。客户不确认，判得越多，假红越多，可信度越低。而且 Q1/Q2 还没回，现在改判据等于在等一个会变的答案上动工。
- 本轮只出两份文档（本文件 + 确认单）+ 回执后的「改动说明」。
- 回执前**不写代码**。改动说明那一步才是真正落判据的时机。

---

## 六、给答辩的三句话

1. **407 是可拆的**：5 行口径无关、402 行挂在两条待确认口径上。我们把这件事写在页面上，不是等客户发现。
2. **语义错分三类**：逻辑上不可能（能硬判）／规矩上不该（要客户给规则）／说法不统一（只提示不判错）。只有第一类能靠机器定案。
3. **关闭只认两条**：同一道判据复跑归零，且客户回执确认。没回执的，标「未覆盖」，不猜默认值。

## 附：数字怎么复跑（只读，不改库）

DSN：`postgresql://postgres:postgres@localhost:5432/fde_client`

```sql
-- 9 条时间倒置（维修单整段早于缺陷发生）
SELECT r.ro_no, r.rec_id, r.opened_at, r.closed_at, d.captured_at,
       round(extract(epoch FROM (d.captured_at - r.closed_at))/3600.0, 1) AS gap_h
FROM biz_repair_order r JOIN biz_defect_record d ON r.rec_id = d.rec_id
WHERE r.closed_at IS NOT NULL AND r.closed_at < d.captured_at ORDER BY r.ro_no;
-- 预期 9 行；把 closed_at 换成 opened_at 仍是同样 9 行

-- 维修单设备与缺陷设备不一致
SELECT count(*) AS ro, count(*) FILTER (WHERE r.equip_no <> d.equip_no) AS mismatch
FROM biz_repair_order r JOIN biz_defect_record d ON r.rec_id = d.rec_id;   -- 40 / 40

-- NG 无维修单，以及维修单挂的是 NG 还是 OK
SELECT count(*) FILTER (WHERE d.judge='NG'
       AND NOT EXISTS (SELECT 1 FROM biz_repair_order r WHERE r.rec_id=d.rec_id)) AS ng_no_ro
FROM biz_defect_record d;                                                 -- 127
SELECT d.judge, count(*) FROM biz_defect_record d
JOIN biz_repair_order r ON r.rec_id=d.rec_id GROUP BY 1;                   -- NG 20 / OK 20

-- 三级报警两列全空
SELECT level, count(*), count(*) FILTER (WHERE acked_by IS NULL OR acked_by=''),
       count(*) FILTER (WHERE cleared_at IS NULL)
FROM biz_alarm GROUP BY level ORDER BY level;                             -- 1/2 级 0 空；3 级 40 空

-- 工位两套叫法
SELECT station_no, count(*) FROM biz_work_order GROUP BY 1 ORDER BY 1;     -- 1–4 号工位，各 15
SELECT station_no FROM md_station ORDER BY 1;                             -- 产线A-01 … 产线D-04

-- 为什么说「无法唯一归属」：产线/工位ID 两列存在但全空
SELECT count(*) FILTER (WHERE prod_line IS NULL) AS prod_line_null,
       count(*) FILTER (WHERE station_id IS NULL) AS station_id_null
FROM biz_work_order;    -- 60 / 60（缺陷表同样 302 / 302）

-- 缺陷名的左右不对称
SELECT regexp_replace(defect_name,'（[左右]）','') AS base,
       count(*), count(DISTINCT defect_name), string_agg(DISTINCT defect_name,' | ')
FROM biz_defect_record GROUP BY 1 HAVING count(DISTINCT defect_name) > 1 ORDER BY 2 DESC;
```
