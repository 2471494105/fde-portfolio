# 答辩前一条命令自检：`pre_demo.py`

> T44｜2026-11-27｜新增 `mock-mes/scripts/pre_demo.py`
>
> 一句话：**现场出问题时，人缺的不是能力，是「先查哪一项」。**

## 一、为什么另起一份，不复用 preflight

`fde-diagnosis-agent/scripts/preflight.py` 回答的是「这 373 秒评测跑下去有没有意义」：8010 端口、库是不是种子态、事实层有没有缺口。它**不碰 8021**，也不管页面。

而答辩现场要确认的是另一组事：服务在不在听、巡检是不是停了、五个验收还绿不绿、**页面上的字是不是刚改过的那一版**。这些以前要手记五个脚本路径、记用哪个 venv、一个个跑——紧张的时候一定漏。

`pre_demo.py` 只回答一个问题：**现在这台机器，能不能上台。**

## 二、六段，每段给「下一个动作」

| 段 | 查什么 | 红了怎么办 |
|---|---|---|
| 1 环境 | fde venv 在不在、服务目录对不对 | 后面全部无意义 |
| 2 服务 | `/healthz` + 连库毫秒 | 打印起服务的两条命令；`--start` 直接隐藏窗口拉起 |
| 3 巡检 | `alert_sweep` 上次跑于多久前、是否 silent | 提示跑 `patrol.py` 或 `Start-ScheduledTask "FDE-Patrol"` |
| 4 五个验收 | `verify_console` / `verify_obs` / `verify_demo` / `verify_check_rules` / `verify_problem` | 只报名字与末行结论，不 dump 全文 |
| 5 页面口径 | 直接读 `/console` 的 HTML：首屏三卡、题面块、`<details class="tech">` | 多半是改了 html 没重启 8021 |
| 6 结论 | 绿/红 + 总耗时 | 红时只提示「先做第一条」 |

**第 5 段是这份脚本唯一不可替代的地方**：脚本全绿不等于页面是新的（改了 `console.html` 忘记重启，`verify_console` 会跟着一起红；但只改了 `obs.py` 字段、页面没重启时，脚本可能都绿而页面没数据）。所以它不信脚本，直接读渲染后的 HTML。

不跑的东西：`verify_demo_closeout` 默认不跑——它会写两行台账（361/362），演示前每跑一次都要重解释一遍数字；要跑就 `--with-closeout`，并在输出里写明「台账已 +2 行」。

## 三、写的过程中修掉的两个真错

1. **读错了端点**：第一版从 `/v1/obs/summary` 取 `checks`，跑出来是 `[!] 读不到扫描状态：'checks'`。摘要接口只有接口指标与新鲜度，扫描状态在 `/v1/obs/runs` 的 `checks` 里。**没有真跑一遍，这个键错误会一直藏着**，直到某次现场「巡检段永远黄」。
2. **`global` 声明顺序**：用 `argparse` 的 `default=BASE` 先把模块常量用了，再写 `global BASE`，Python 直接 `SyntaxError: name 'BASE' is used prior to global declaration`。改成 `default=None`、解析后再赋值。

第 2 条代价很小但值得记：**脚本能不能跑，只有跑起来才知道**；AST 能过不代表能执行，执行能过不代表路径对。

## 四、反证（两次都按「必须能红」验）

- **服务不在时**：`--base http://127.0.0.1:8099`（没人听）→ `[红] 2 项没过：8021 没在听, 读 /console 失败`，`exit=1`；
- **`--start` 能不能真拉起来**：先 `Stop-Process` 杀掉 8021，再 `--start` → `… 没在听，按 --start 拉起` → `[ok] 已拉起 · 连库 78.7 ms`，全程 `exit=0`；
- **正常路径**：39 秒内五项全绿（`verify_console` 用 Edge 无头渲染，是最慢的一项，10–13 s）。

## 五、限制

1. **`--base` 不传导**：五个验收脚本各自写死 `127.0.0.1:8021`。真换端口，要连它们一起改；现在只保证默认端口这条路径被验过。
2. **它不判「讲得好不好」**：台词对不对只有手卡能管，语气更是人的事。它只保证「屏幕上的东西是真的、是新的」。
3. **依赖 Edge**：`verify_console` 用本机 Edge 无头渲染，机器上没有 Edge 会红——那是环境问题，不是代码问题。
4. **冷启动会更慢**：首次拉起 Edge 可能 60 s+；`--start` 刚拉起服务时，第 4 段前几项也会慢。
5. **不清理演示残留**：收口演示留下的两行台账、`/v1/problem/999999` 那条 404 计数都不管（前者要人重解释，后者重启即清零）。
6. **它自己也只在 Windows 上验过**：`creationflags=CREATE_NO_WINDOW`、`venv\Scripts\python.exe` 都带 Windows 假设。

## 六、和手卡的关系

手卡第十节「开录前 60 秒」现在是第 0 步跑这条命令，第 1 步才看 Postgres 与 healthz。**顺序不能反**：先知道「能不能上台」，再去调窗口字号、开标签页——后者是表演，前者是事实。
